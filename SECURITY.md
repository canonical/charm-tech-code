# Security policy

## Supported versions

This repository contains tooling that Charm Tech's own repositories run in their GitHub workflows. There are no releases, so workflows pin this repository by commit SHA. Only the tip of `main` gets fixes. To pick up a fix, update the pinned SHA.

## Reporting a vulnerability

Please provide a description of the issue, the steps you took to create the issue, the affected commit, and, if known, mitigations for the issue.

The easiest way to report a security issue is through [GitHub's security advisory for this project](https://github.com/canonical/charm-tech-code/security/advisories/new). See [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability) for instructions on reporting using GitHub's security advisory feature.

The GitHub repository admins will be notified of the issue and will work with you to determine whether the issue qualifies as a security issue and, if so, in which component. We will then figure out a fix and coordinate its release.

You may also send email to security@ubuntu.com. If you want to encrypt your email, follow [Canonical's reporting instructions](https://ubuntu.com/security/disclosure-policy#contact-us).

If you have a deadline for public disclosure, please let us know. Our vulnerability management team intends to respond within 3 working days of your report. This project aims to resolve all vulnerabilities within 90 days.

The [Ubuntu Security disclosure and embargo policy](https://ubuntu.com/security/disclosure-policy) contains more information about what you can expect when you contact us, and what we expect from you.
